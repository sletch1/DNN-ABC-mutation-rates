# DNN-ABC: neural surrogates for approximate Bayesian computation of mutation rates

Code, data and manuscript for *Deep Neural Network Surrogates for Approximate Bayesian Computation: A Simulation Study for
Mutation-Rate Estimation in Markov Branching Processes* (Letchumanan, Zhu, Wu).

The paper asks whether a neural network can replace the Gaussian process inside **GPS-ABC**, the sampler of
Lu, Zhu & Wu (2023), *Estimating mutation rates in a Markov branching process using approximate Bayesian computation*,
J. Theoretical Biology 565:111467, and when that helps. It has two studies:

| | Model | Folder |
|---|---|---|
| **Study I** | one parameter, constant mutation probability `p` | [`1D/`](1D/README.md) |
| **Study II** | two-stage mutation rate with differential growth, `(p1, p2, τ, δ)`: the original paper's Simulation Study 2, in its own regime | [`4D/`](4D/README.md) |

Study II is the main study. It compares **GPS-ABC** (the original authors' MATLAB code, run on our data), **DNN-ABC** (the same
sampler with a zero-aware neural surrogate, and a control trained on only the original design size) and **NPE** (amortized neural
posterior estimation, trained on the same simulations; the estimator is chosen from seven candidates in
`4D/inference/npe_candidates.py`), with simulation-based calibration over prior draws. The data generator is
checked against the training sets the original authors released (`4D/tests/validate_vs_published.py`).


## Layout

```
manuscript.tex / .pdf      the paper (figures/ and tables/ are generated by the code)
1D/                        Study I: simulator, surrogate, ABC sampler, tables, figures
4D/                        Study II: simulator, data generation, surrogate + architecture search,
                           DNN-ABC, NPE, calibration, MATLAB GPS-ABC wrapper, analysis
RCode/                     R simulators and the Study I ground-truth generators
Ricker/                    second zero-inflated benchmark (stochastic Ricker map)
Makefile                   `make paper` runs every experiment (skipping finished ones), then rebuilds numbers, tables, figures and PDFs
tables/                    generated by 4D/analysis/ and pulled into the manuscript (figures: 4D/figures, 1D/results/figures)
submission_package/        not tracked: `make package` rebuilds the self-contained journal submission folder (manuscript, figures, tables)
notes/                     private drafts and status notes (not tracked)
paper_code_discrepancy.md  where the published paper and the released code disagree, and which we follow
```

**Rule used throughout:** where the original paper and the original code disagree, we follow the paper
(`paper_code_discrepancy.md`).

## Requirements

Python 3.9+ with `requirements.txt` (`numpy`, `pandas`, `scipy`, `matplotlib`, `scikit-learn`, `torch`, `sbi`); no GPU. The optional
BayesFlow candidate in the NPE comparison also needs `bayesflow>=2.0` (run with `KERAS_BACKEND=torch`).
Running the original GPS-ABC sampler (Study II baseline) additionally needs MATLAB with the Statistics and
Parallel Computing toolboxes. Heavy steps (data generation, the architecture search, GPS-ABC) are written for a
multi-core Linux server; see `4D/server/`.

## Reproducing

### 1. Set up (once)

```bash
git clone <this repository> && cd DNN_ABC
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt        # numpy, pandas, scipy, matplotlib, scikit-learn, torch, sbi, ...
```

You also need `latexmk` and a LaTeX distribution (MacTeX/BasicTeX or TeX Live) to compile the PDFs. The `Makefile` uses
`.venv/bin/python` automatically when it exists; otherwise pass `PY=/path/to/python`. No GPU is needed.

### 2. Run everything from scratch

```bash
make check                 # 10 s: tests the simulator
make paper                 # runs ALL experiments, then builds every number, table, figure and both PDFs
```

`make paper` runs, in order: Study I (`1D/`), Study II (`4D/`: data generation, architecture search, surrogate, DNN-ABC, NPE,
calibration, controls, repair checks, reference posterior, seven NPE candidates), the Ricker benchmark, and finally the numbers,
tables, figures and `manuscript.pdf` / `manuscript-supplementary.pdf`. **A complete run from an empty `results/` takes days on a
multi-core machine** (the 1D comparison and the 4D architecture search, calibration and GPS-style chains dominate), so run it with
`nohup`/`tmux`, e.g. `nohup make paper CORES=16 > run.log 2>&1 &`.

* **Resumable.** Each step is skipped if its output file already exists, so an interrupted run continues where it stopped, and on this
  repository (which ships the finished results) `make paper` only rebuilds the numbers, tables, figures and PDFs (about 20 seconds).
  To redo one step, delete its output file and run `make paper` again; `make rerun-all` deletes every experiment output (after asking).
* **Cores.** `CORES=N` caps the number of worker processes (default: all cores).
* **Test the whole pipeline in minutes.** `make rerun-all && make paper SMOKE=1` runs every step at toy size (tiny data, short
  chains). The output is meaningless; it only proves every step runs. Run `make rerun-all` again before a real run.
* **Parts.** `make study1`, `make study2` and `make ricker` run one study; `make paper-fast` skips all experiments and rebuilds
  numbers, tables, figures and PDFs from the stored results.
* **Not run by `make paper`.** The GPS-ABC chains (MATLAB, the original authors' code in `Original_Paper_Code/`; hours per chain, see
  [`4D/HOW_TO_RUN.md`](4D/HOW_TO_RUN.md) step 6) and the check against the authors' released training sets (needs
  `Original_Paper_Code/training`). If their results are present they are used; otherwise the committed summaries in
  `4D/results/tables` are, and the Makefile says so.

Individual steps, with their exact commands, are in [`1D/HOW_TO_RUN.md`](1D/HOW_TO_RUN.md) (Study I) and
[`4D/HOW_TO_RUN.md`](4D/HOW_TO_RUN.md) (Study II). Every table and figure of the paper is regenerated from the result files by
`4D/analysis/` and `1D/analysis/`, with no hand-copied numbers.

## Notes on provenance

* The published paper's PDF and the cited papers are not redistributed here (copyright); cite them via their DOIs.
* This repository contains only the authors' own code and data. The original authors' released MATLAB code (Lu et al. 2023,
  https://doi.org/10.1016/j.jtbi.2023.111467) is **not** redistributed: obtain it from them and place it in `Original_Paper_Code/`
  to run the GPS-ABC baseline (`4D/gps_abc/`). Our Study II GPS-ABC runs changed two things in it: a memory-safe negative-binomial draw
  in `mut_bMBP_rev.m` (the original sums `geornd` over a vector of about exp(tau) entries) and a checkpointing copy of `ABC_mu2a.m`
  (see the supplement, S3, and `paper_code_discrepancy.md`). The adapted copies are not redistributed either.

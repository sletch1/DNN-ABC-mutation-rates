\abstract{Approximate Bayesian computation (ABC) enables likelihood-free inference for stochastic simulators, but slow simulators, such as the branching-process models used to estimate mutation rates in Luria--Delbr\"uck experiments, make it infeasible. A standard remedy substitutes a Gaussian-process (GP) surrogate inside an ABC Markov chain Monte Carlo (MCMC) sampler (GPS-ABC), but the GP's cubic fitting cost limits the simulator output it can use, and in the original four-parameter study one chain takes days. We ask whether a neural-network surrogate calibrated by split-conformal prediction can make the same substitution. A one-dimensional benchmark shows tighter calibrated intervals and a 68- to 2,000-fold speedup over exact ABC-MCMC. The main study is the four-parameter two-stage model, run in the original study's regime after checking that our data generator is statistically indistinguishable from theirs. The summary statistic is exactly zero for 30\% of data sets; a zero-aware network fits it at the noise floor where a GP fit to the original $1{,}500$ points is $1.45$ times above it. Against the original authors' own sampler on the same data sets, it matches the accuracy of GPS-ABC with $1.7$ to $3.6$ times shorter intervals for the second mutation probability, in about forty seconds per data set. A neural posterior estimator (NPE) trained on the same simulations, with no surrogate or chain, agrees on what the data identify and is better calibrated, while the surrogate-based samplers are sharper and mildly overconfident.}

\section{Introduction}
\label{sec:intro}
% =============================================================================

Approximate Bayesian computation (ABC) makes Bayesian inference possible for
stochastic models whose likelihood is intractable but which can be simulated
forward \citep{beaumont2002,marjoram2003,marin2012}. The basic ABC-MCMC sampler
\citep{marjoram2003} accepts a proposed parameter $\theta'$ in proportion to how
closely a simulated summary statistic matches the observed one. Every iteration
costs at least one forward simulation, so when the simulator is expensive the
per-iteration cost dominates the analysis and can put a full posterior
exploration out of reach.

\citet{lu2023} study this problem for a two-type Markov branching process (MBP)
model of microbial mutation, used to estimate mutation probabilities from
Luria--Delbr\"uck-style fluctuation experiments. Their exact simulator
(Algorithm~2) tracks the process cell by cell, and a single call takes from a
fraction of a second to several minutes. To make ABC-MCMC tractable they apply
\emph{GPS-ABC} \citep{meeds2014}: fit a Gaussian process (GP) regression
surrogate to a modest design of simulator outputs, then use the GP's predictive
mean and variance in place of the simulator inside the acceptance step. This is
the source of their reported two-to-three-order-of-magnitude speedup.

The GP brings a scaling limit that is well known and, here, binding. Fitting an
$n$-point GP costs $O(n^3)$ and a query costs $O(n)$ in the dense
implementation used at this problem size. \citet{lu2023} accordingly work with
about $50$ design points in the one-dimensional case and $1{,}500$ in their
four-parameter extension, and note that GPS-ABC can be \emph{less} accurate than
plain ABC-MCMC when the design must be built from the expensive exact simulator.
We ask:

\begin{quote}
\emph{Can a neural-network surrogate replace the Gaussian process inside the same
ABC-MCMC procedure, and under what conditions does it help?}
\end{quote}

A feedforward network has no cubic fitting term and its query cost is flat in
the size of its training set. It also gives up something the GP provides for
free: a predictive variance. Inside the ABC acceptance kernel that variance is
consumed directly, so a network must be built to produce one and then calibrated
(Section~\ref{sec:method}). That requirement, rather than the regression
itself, makes the substitution non-trivial.

\noindent\textbf{Contributions.} The paper's centre of gravity is the four-parameter
two-stage model of \citeauthor{lu2023}'s Simulation Study~2 (Study II); the
one-dimensional model (Study I) is the benchmark that shows where a surrogate
matters.
\begin{enumerate}[label=(\roman*),leftmargin=*,itemsep=2pt,topsep=2pt]
\item \emph{A calibrated, zero-aware neural surrogate.} A heteroscedastic network
with split-conformal calibration \citep{lei2018} that substitutes for the GP in
\citeauthor{lu2023}'s sampler with no other change to the inference algorithm. In
the two-stage model the summary statistic is exactly zero on about $30\%$ of data
sets and the two features $(\bar d,s)$ it is built from are strongly correlated, so
the network is a hurdle model for a pair of correlated features rather than a
regression on $\log_{10}\bar d$.
\item \emph{A like-for-like comparison with the original sampler.} We run the
original authors' MATLAB GPS-ABC on the same simulated data sets, in the original
study's regime ($t_p=20$, $p\in[10^{-11},10^{-7}]$, four parameters), after checking
that our data generator is statistically indistinguishable from theirs at their own
design points. A control trained on only the original design size separates the effect
of more simulation from the effect of the surrogate.
\item \emph{A neural posterior estimator as an independent reference.} NPE learns the
posterior directly from the same simulations, with no surrogate likelihood, no kernel
and no Markov chain. It matters here for three reasons. It shows whether the surrogate
and sampler are needed at all in four dimensions, since it uses exactly the same data and
features. It separates the two ways a surrogate-based posterior can go wrong, the
surrogate's variance model and the sampler, because it has neither. And, being
amortized, it returns posterior draws for a new data set in seconds with no further
simulation, which GPS-ABC and DNN-ABC cannot do.
\item \emph{Identifiability, not the surrogate, limits accuracy.} The data identify
$p_2$ and, loosely, $\delta$, and not $p_1$ or $\tau$. A neural posterior estimator (NPE)
trained on the same simulations and the surrogate-based sampler agree on this, which
makes it a property of the summary statistic and not of either method.
\item \emph{Calibration diagnostics that do not saturate.} Coverage at a fixed
truth is $1.000$ for any nearly unidentified parameter because the interval spans the
prior. We use simulation-based calibration over truths drawn from the prior
\citep{talts2018} together with posterior contraction: NPE is calibrated and less sharp,
the surrogate-based samplers sharper and mildly overconfident.
\item \emph{A one-dimensional benchmark.} The one setting where surrogate error
does bind: the network's input-dependent variance yields tighter,
still-calibrated intervals than the GP, and DNN-ABC is $68$ to over $2{,}000$
times faster than exact ABC-MCMC.
\item \emph{Negative results we report rather than tune away.} More training
data does not help once the surrogate is at the noise floor ($1{,}500$ design points
are as good as $10{,}000$), residual networks are no better than plain MLPs, and
modelling the correlation of the two features improves the likelihood but does not
restore nominal coverage.
\end{enumerate}

\noindent\textbf{Related work.} GPS-ABC is one instance of a line of work using
Gaussian processes to reduce simulator calls in likelihood-free inference:
\citet{wilkinson2014} models the ABC log-likelihood surface directly,
\citet{gutmann2016}'s BOLFI uses Bayesian optimization to place the next
expensive simulation, and \citet{jarvenpaa2021,jarvenpaa2023} extend this to
noisy, parallel and predictive settings. All inherit the $O(n^3)$ fitting cost;
none substitutes a neural surrogate for the GP, which is the substitution
studied here. A separate literature avoids the GP-versus-network choice by
learning the posterior (or likelihood, or likelihood ratio) directly with a
neural density estimator trained on simulator draws
\citep{papamakarios2016,greenberg2019,cranmer2020}, implemented in toolkits such
as \texttt{sbi} \citep{tejerocantero2020}. These methods are \emph{amortized}:
training is paid once and new data sets need no further simulation or MCMC,
which GPS-ABC, DNN-ABC and exact ABC-MCMC cannot offer. We include NPE in Study II, the higher-dimensional
study, to make that trade-off concrete and to test what the sampler and the surrogate's variance model add on top of the same
simulations; Section~\ref{sec:methods2} gives the reasons in full. The coverage question is motivated by
\citet{talts2018} and \citet{hermans2022}, who report that posterior
approximations routinely pass regression-level diagnostics yet fail to cover the
truth at the stated rate when checked directly, and by \citet{fanwhite2026},
who show that a narrow NPE proposal can give a biased posterior that still
reproduces the observed summaries. Section~\ref{sec:sim1D_coverage}'s distinction
between the surrogate's regression coverage and the ABC posterior's coverage is
an instance of the same failure mode.

The paper proceeds as follows. Section~\ref{sec:background} reviews the model
and GPS-ABC, Section~\ref{sec:method} develops the surrogate, and
Sections~\ref{sec:sim1D} and \ref{sec:sim3D} report the two studies.
Section~\ref{sec:discussion} discusses implications and limitations and
Section~\ref{sec:repro} describes the reproducible pipeline.

\section{Background: ABC for the Markov Branching Process Model}
\label{sec:background}
% =============================================================================

\subsection{The mutation model and the observed statistic}

Following \citet{lu2023}, a population initiated by a single wild-type cell
grows for a fixed observation period under a two-type Markov branching process
(MBP). Three quantities govern it: the per-division mutation probability $p$,
the division-rate parameter $a$ (which sets the time scale), and the mutant
relative growth rate $\delta$. We take $a=1$ throughout and, in Study I,
$\delta=1$ as well; Study II frees $\delta$. We refer to \citet{lu2023} for the full
construction and for their Algorithm~2 (an exact, cell-by-cell simulator) and
Algorithm~4 (a fast approximate simulator). We re-implement both in Python and
check the result against the training data the original authors released
(Section~\ref{sec:validation}).

An experiment consists of $J$ independently plated parallel cultures, each
grown from one wild-type cell for the same fixed time. Culture $j$ yields a
final wild-type count $Z_j$ and mutant count $X_j$. Following
\citeauthor{lu2023}, we work with the scalar summary
\[
\dbar \;=\; \frac{1}{J}\sum_{j=1}^{J} \sqrt{X_j / Z_j},
\]
and, for the two-stage model, its fourth-root analogue and the standard deviation of the same values (Section~\ref{sec:groundtruth3D}).
Every regression below models $\log_{10}\dbar$ rather than $\dbar$, because
$\log_{10}\dbar$ varies smoothly and close to linearly in $\theta \equiv
\log_{10} p$ (\citealp{lu2023}, Figure~2), a target both GP and neural-network
regression fit considerably better.

\subsection{ABC-MCMC and GPS-ABC}
\label{sec:abcmcmc}

Write $\theta = \log_{10} p$. Given an observed statistic $\dbar_{\mathrm{obs}}$,
classical ABC-MCMC \citep{marjoram2003} targets
\[
\pi_\epsilon(\theta \mid \dbar_{\mathrm{obs}}) \;\propto\; \pi(\theta)\,
\mathbb{E}_{S \sim F_\theta}\!\left[K_\epsilon\!\left(\dbar_{\mathrm{obs}}, S\right)\right],
\]
with a smoothing kernel $K_\epsilon$ of bandwidth $\epsilon$. The ``exact''
baseline throughout this paper is not this literal kernel average but Wood's
\citep{wood2010} \emph{synthetic likelihood}: at each proposed $\theta'$ we draw
$n_s$ pilot simulations, take their sample mean $m(\theta')$ and variance
$v(\theta')$, and score $\dbar_{\mathrm{obs}}$ against a matched Gaussian,
\[
\hat\pi_\epsilon(\dbar_{\mathrm{obs}} \mid \theta') \;=\;
\mathcal{N}\!\left(\dbar_{\mathrm{obs}};\; m(\theta'),\; \epsilon^2 + v(\theta')\right).
\]
This is exactly the likelihood form the surrogates use, with a predicted
variance $\sigma_\phi(\theta')^2$ in place of $v(\theta')$, so every column of
the result tables shares one likelihood and differs only in how
$(m(\theta), v(\theta))$ is obtained. Algorithm~\ref{alg:abcmcmc} states the
shared Metropolis--Hastings sampler: a truncated-exponential prior on $\theta$
(uniform in the multi-parameter study) and a truncated-normal random-walk
proposal.

\begin{algorithm}[H]
\caption{ABC-MCMC (Metropolis--Hastings, synthetic likelihood)}
\label{alg:abcmcmc}
\begin{algorithmic}[1]
\State Initialize $\theta_0$; set tolerance $\epsilon$, simulator-repeat count $n_s$.
\For{$t = 1, \dots, T$}
  \State Propose $\theta' \sim q(\cdot \mid \theta_{t-1})$ (truncated-normal random walk)
  \State Obtain $(m(\theta'), v(\theta'))$: either (a) simulate $n_s$ times from $F_{\theta'}$ and take their sample mean and variance, or (b) evaluate a surrogate's predicted mean and variance $(\mu_\phi(\theta'), \sigma_\phi(\theta')^2)$ (Section~\ref{sec:method})
  \State Compute acceptance probability
  \[
  \resizebox{0.95\linewidth}{!}{$\displaystyle\alpha \;=\; \min\!\left(1,\; \frac{\pi(\theta')\,q(\theta_{t-1}\mid\theta')}{\pi(\theta_{t-1})\,q(\theta'\mid\theta_{t-1})}\,\cdot\,\frac{\hat\pi_\epsilon(\dbar_{\mathrm{obs}} \mid \theta')}{\hat\pi_\epsilon(\dbar_{\mathrm{obs}} \mid \theta_{t-1})}\right)$}
  \]
  \State Set $\theta_t = \theta'$ with probability $\alpha$, else $\theta_t = \theta_{t-1}$
\EndFor
\State \Return $\{\theta_t\}_{t=B+1}^{T}$ after discarding $B$ burn-in draws
\end{algorithmic}
\end{algorithm}

Step 4(a) is the expensive one. \emph{GPS-ABC} \citep{meeds2014}, applied by
\citet{lu2023} to this model, instead fits a GP to a design
$\{(\theta_i, \dbar_i)\}_{i=1}^n$ of simulator outputs \emph{once}, and at every
iteration uses step 4(b): the GP's predictive mean and variance replace
$(m(\theta'), v(\theta'))$ directly. This sets the standard any replacement
must meet. It is not enough to predict the mean accurately; the variance must
also be calibrated, because the two failure modes are asymmetric and both
corrupt the posterior. An overconfident $\sigma$ inflates the acceptance rate
where the surrogate does not know the response, and an underconfident one
over-rejects.

The GP's fitting cost is $O(n^3)$ and its per-query cost $O(n)$, since the
predictive mean and variance require solving a system with the full training
kernel matrix. \citet{lu2023} report about $50$ design points in the
one-dimensional case and $1{,}500$ initial points in a four-parameter extension,
and note that GPS-ABC trained on the exact simulator can be less accurate than
uncorrected ABC-MCMC, plausibly because the cubic cost forces a small design
when each design point comes from the expensive exact simulator.

\section{A Neural-Network Surrogate for ABC}
\label{sec:method}
% =============================================================================

We replace the GP in step 4(b) of Algorithm~\ref{alg:abcmcmc} with a neural
network $f_\phi$ trained to predict both the mean and the variance of
$\log_{10}\dbar$ as a function of the parameters of interest. The substitution
is deliberately minimal: the sampler, the acceptance ratio and the convolution
with $\epsilon^2$ are exactly those of GPS-ABC, so any difference in the results
is attributable to the surrogate. We call the procedure \emph{DNN-ABC}. The two
ingredients that let the network stand in for the GP are an input-dependent
predictive variance and a guarantee that it is calibrated.

\subsection{Heteroscedastic regression}
\label{sec:hetero}

$f_\phi$ has two output heads, $\mu_\phi(x)$ and $\log\sigma^2_\phi(x)$, where
$x$ is $\theta=\log_{10}p$ alone (Study I) or $(\log_{10}p_1, \log_{10}p_2,
\tau, \log_{10}\delta)$ (Study II), with no derived features. Both heads are trained jointly by
minimizing the Gaussian negative log-likelihood
\begin{equation}
\label{eq:nll}
\mathcal{L}(\phi) \;=\; \frac{1}{n}\sum_{i=1}^n \left[
\frac{\left(y_i - \mu_\phi(x_i)\right)^2}{2\,\sigma_\phi^2(x_i)}
\;+\; \frac{1}{2}\log \sigma_\phi^2(x_i)
\right],
\end{equation}
with $y_i = \log_{10}\dbar_i$. Unlike squared-error training, this targets an
\emph{input-dependent} predictive variance, the network's analogue of the GP's
posterior variance. That is a requirement, not a refinement: the
replicate-to-replicate noise in $\log_{10}\dbar$ is far from homoscedastic
(Sections~\ref{sec:sim1D} and \ref{sec:arch4D}), and a GP with a single noise
term cannot represent that shape.

\subsection{Split-conformal calibration}
\label{sec:conformal}

A trained variance head approximates the true conditional variance from a
finite sample; nothing in Eq.~\eqref{eq:nll} guarantees it is calibrated. Since
the acceptance step consumes it directly, we apply split-conformal calibration
\citep{lei2018}. On a held-out calibration split of size $m$ we form scores
\[
s_i \;=\; \frac{\left|y_i - \mu_\phi(x_i)\right|}{\sigma_\phi(x_i)}, \qquad i=1,\dots,m,
\]
and set the calibration factor $\hat c$ to the $\lceil (m+1)(1-\alpha)
\rceil / m$ empirical quantile of $\{s_i\}$. The calibrated $(1-\alpha)$
predictive interval is $\mu_\phi(x) \pm \hat c\, \sigma_\phi(x)$, and for
exchangeable calibration and test points it has marginal coverage of at least
$1-\alpha$ in finite samples, with no distributional assumption \citep{lei2018}.
We use $\alpha = 0.05$ and call this the surrogate's \emph{regression
calibration}, to distinguish it from the empirical coverage of the downstream
ABC credible intervals, a different quantity with no equivalent guarantee
(Sections~\ref{sec:sim1D_coverage} and \ref{sec:sim3D_sbc}). The calibrated
$\hat c\,\sigma_\phi(x)$ is also what enters the acceptance kernel, so the
uncertainty that is validated is the uncertainty the sampler uses.

\subsection{Simulator validation}
\label{sec:validation}

Every number below rests on our re-implementations of the simulators of
\citet{lu2023}, so we check them against the original authors' own data. They
release the training sets they used for GPS-ABC: for the four-parameter model,
$1{,}500$ design points at which they ran their fast simulator five times, and
for the constant-rate model, $1{,}500$ points $\times$ ten runs at each of five
mutation rates. At each of their design points we draw $400$ values from our
simulator and compute the randomised probability-integral transform of each
value they stored (the statistic has an atom at zero, so ties are randomised).
If the two simulators agree at every design point, the transforms are i.i.d.
uniform, which a Kolmogorov--Smirnov test checks, overall and within quarters of
each parameter's range. The four-parameter data are not rejected
(overall $p=0.08$ on $7{,}500$ values; the smallest of $16$ quarter-range
$p$-values is $0.005$ at $400$ draws and $0.08$ at $1{,}500$, above the
Bonferroni threshold of $0.003$ in both), nor are the constant-rate data
($p=0.22$, $0.52$, $0.69$ at $p=10^{-8}$, $10^{-6}$, $10^{-4}$; $15{,}000$ values
each). The constant-rate exact simulator is additionally checked against the plating-time
equation of \citet{lu2023} (agreement to $3\times10^{-5}$ with the R solver). The
design points themselves cannot match theirs draw for draw, since a Latin hypercube
is random; what we match is the mechanism.

\subsection{Simulation design and reporting}
\label{sec:ademp}

We follow the ADEMP structure of \citet{morris2019}. \emph{Aims}: compare MOM,
MLE, exact ABC-MCMC, GPS-ABC and DNN-ABC in Study I, and GPS-ABC, DNN-ABC and NPE in
Study II (the constant-rate MOM and MLE do not apply there, and exact ABC-MCMC is out
of reach at $t_p=20$), on point accuracy, interval precision, calibration and cost.
\emph{Data-generating mechanisms}: the simulators of \citet{lu2023}, checked against
the training data they released (Section~\ref{sec:validation}), at the parameter
settings of Sections~\ref{sec:sim1D_results} and \ref{sec:groundtruth3D}.
\emph{Estimands}: $p$ (via $\theta=\log_{10}p$) in Study I and
$(p_1,p_2,\tau,\delta)$ jointly in Study II. \emph{Performance measures}: MSE and
normalized RMSE of $\hat p$, mean 95\% credible-interval length, empirical coverage, and
wall-clock time (per 100 MCMC iterations in Study I, per data set in Study II); for
Study II also the distance of each posterior from the GPS-ABC posterior it is meant to
replace, simulation-based calibration and posterior contraction
(Section~\ref{sec:sim3D_sbc}).

Study I is evaluated over $R=40$ independent replicated data sets per cell. Study II
uses $100$ observed data sets per truth case for DNN-ABC and NPE and, because one
GPS-ABC chain takes days (Section~\ref{sec:gps}), the first five of the same data sets
for GPS-ABC, so every comparison with it is paired. Every comparison carries its Monte
Carlo standard error: for $e_r = (\hat p_r - p)^2$,
$\widehat{\mathrm{MCSE}} = \mathrm{sd}(e_r)/\sqrt{R}$. For two methods we report
the MSE gap in units of its combined MCSE (the $\Delta/\mathrm{SE}$ column of
Table~\ref{tab:mse1D}). This is a descriptive diagnostic of whether a point
comparison is resolved at the replicate count, not a hypothesis test; we call a
difference resolved when $|\Delta/\mathrm{SE}|>2$.

\section{Study I: A Benchmark with One Parameter}
\label{sec:sim1D}
% =============================================================================

Study I reproduces \citeauthor{lu2023}'s constant-rate benchmark: $a=\delta=Z_0=1$
and only $p$ varying. Its role in this paper is to show \emph{where} a surrogate
matters; the multi-parameter inference question is Study II. Ground truth is
$101$ log-spaced values of $p$ with $\log_{10}p \in [-8,-2]$, ten replicates each
($1{,}010$ rows), $J=100$. We split \emph{by replicate} rather than by grid
point, so every $p$ appears in every split and a split tests generalisation to
fresh noise, with no leakage: replicates 1--5 train ($505$ rows), 6--8 calibrate
and early-stop ($303$), 9--10 are held out ($202$). The GPS-ABC baseline is fit
on replicates 1--8, so both surrogates see the same data and neither sees the
test replicates.

The ABC comparison evaluates observed data sets at $J \in \{10, 50, 100\}$
cultures. Both surrogates are trained separately for each $J$: for $J \in
\{10, 50\}$ a $J$-culture $\dbar$ is rebuilt from the same simulated data by
averaging a random $J$-subset of the $100$ recorded per-culture values (five
subsets per row), so no new simulator calls are needed.
Section~\ref{sec:sim1D_coverage} shows why this matters.

\subsection{Architecture}
\label{sec:arch1D}

The network is a shallow funnel MLP: input $\theta=\log_{10}p$, two
GELU-activated dense layers of width $32$ and $16$ ($626$ parameters), and the
two linear heads of Section~\ref{sec:hetero}. It is trained with Adam under
early stopping on calibration-split NLL, weight decay $10^{-5}$ and no dropout.
The width is the outcome of a two-stage search (activation and normalisation at
a $128$--$64$ baseline, then capacity); full tables are in Supplementary
Material S1.

The one decisive finding is BatchNorm \citep{ioffe2015}: an otherwise reasonable
$128$--$64$ network carrying it fits \emph{eleven times worse} than the same
network without it. BatchNorm's per-minibatch statistics inject batch-dependent
noise and bias predictions near the hard edge of the one-sided $\theta$ domain,
so what closes the gap to the GP is removing a component most practitioners
include by default. Among BatchNorm-free networks, ReLU, SiLU
\citep{elfwing2018}, GELU \citep{hendrycks2016} and tanh are within $7\%$ of one
another (three seeds), a statistical tie; we choose GELU on structural grounds
(smoothness, no dead units). A second round with $7$-network deep ensembles did
not improve on the single network.

Capacity is also nearly irrelevant. A width and depth sweep from $128$--$64$ down
to a linear control (three seeds, then confirmed at paper scale: $40$ replicates,
the full $p\times J$ grid, $600$ MCMC iterations) finds $32$--$16$ the best point
estimate on curve fit and on the downstream task at $14\times$ fewer parameters,
though that margin is not distinguishable from Monte Carlo noise. Every candidate
from $8$ to $128$--$64$ parameters beats the GP baseline, and only the linear
control shows a clear cost. We therefore deploy $32$--$16$ on parsimony, and
report every table and figure below for it; the $128$--$64$ network remains in
Supplementary Material S1 as the architecture the BatchNorm search ran against.
Convolutional and recurrent architectures are not tested here: with one scalar
input a 1-D convolution has no neighbours to convolve over and a recurrent cell
no second step, so both collapse to a linear map.

\subsection{Regression calibration}
\label{sec:sim1D_calib}

Table~\ref{tab:fit1D} reports the surrogate's fit and split-conformal coverage
by split.


\begin{table*}[t]
\centering

\section{Study II: The Two-Stage Mutation Model}
\label{sec:sim3D}
% =============================================================================


Study I holds $a=\delta=1$ and a single constant mutation probability. The
multi-parameter study of \citet{lu2023}, their Simulation Study~2, is a
different model, not the same one with more parameters freed. The mutation
probability is a step function of time,
\begin{equation}
p(t) \;=\;
\begin{cases}
p_1, & 0 < t \le \tau,\\[2pt]
p_2, & \tau < t \le t_p,
\end{cases}
\label{eq:twostage}
\end{equation}
jumping at an unknown transition time $\tau$, and mutants grow at $\delta$ times
the wild-type rate. The motivation is experimental: mutagenesis under
sub-inhibitory antibiotic stress involves a recovery step before plating and so
two distinct mutation regimes. Study II estimates all four parameters jointly,
$\theta=(\log_{10}p_1,\log_{10}p_2,\tau,\log_{10}\delta)$, which is exactly the
problem of \citeauthor{lu2023}'s Simulation Study~2. It is the main study of this
paper. It is run in their regime, $t_p=20$ and $p_1,p_2\in[10^{-11},10^{-7}]$, so
the results can be set directly against theirs, and it uses the same
construction, summary statistic and sampler as the original GPS-ABC study.

\subsection{What is taken from the original study}
\label{sec:groundtruth3D}

The comparison with GPS-ABC is only meaningful if the data the two methods see
are generated by the same mechanism, so the construction follows \citeauthor{lu2023}
throughout (Table~\ref{tab:settings}). Where their paper and their released code
disagree we follow the paper: the parameter box for $\tau$, the threshold $\xi$
for refining the surrogate, the prior on $\tau$, and the order of the
parameters in $\theta$ (the code lists $\log_{10}\delta$ first).

\noindent\textbf{Training data.} A Latin hypercube over the box, built by the
maximin criterion of MATLAB's \texttt{lhsdesign} (best of five random designs;
\citeauthor{lu2023} cite the optimal-design method of \citet{liao2010}), gives
$10{,}000$ design points. Each is simulated five times, a replicate being $J=100$
independent single-culture draws, so the data set has $50{,}000$ rows and $5\times10^{6}$
culture-level draws against the original design's $7{,}500$: $6.7$ times as many
design points and $667$ times as many draws. This is what a surrogate with no
cubic fitting cost can use and a Gaussian process cannot, and we control for it
in Section~\ref{sec:matched}. The whole data set is generated in under a minute on
a 32-core server. As a check on the generator
we compared it with the training set the original authors ship with their code
($1{,}500\times5$ points in the four-parameter box): evaluated at their design
points, our simulator reproduces the fraction of cultures with no mutants
($0.564$ against $0.558$), the mean statistic ($0.00751$ against $0.00752$) and
the replicate standard deviation ($0.00371$ against $0.00365$).

\noindent\textbf{Observed data.} For each truth case we simulate $100$ independent
observed data sets of $J=100$ cultures. Every method, GPS-ABC included, is
applied to the same data sets, which is what makes the comparison paired. We
cannot reuse the original authors' data sets, which were generated with
MATLAB's random-number stream and are not part of their release.

\noindent\textbf{The summary statistic is the fourth root.} \citeauthor{lu2023}
use $\sqrt{X/Z}$ for the constant-rate study but $\sqrt[4]{X/Z}$ for the
two-stage model, to make the response curve ``smooth and non-flat''. Study II
therefore uses $\bar d=\frac1J\sum_j(X_j/Z_j)^{1/4}$ and the standard deviation
$s$ of the same $J$ values, the two features their sampler compares. About
$30\%$ of simulated data sets have $\bar d=0$ exactly, with no mutant in any of
the $100$ cultures, and $27\%$ of the design points have $\bar d=0$ in all five
replicates; every zero has $p_2<10^{-8.8}$, and the proportion of zeros falls
from $0.91$ for $p_2\in[10^{-11},10^{-10}]$ to $0.30$ for $[10^{-10},10^{-9}]$ and $0.001$ above. Study I's $\log_{10}\bar d$
target is therefore undefined on a large part of the box, which shapes the
surrogate (Section~\ref{sec:hurdle}).

\noindent\textbf{A caution about the meaning of $p$.} We use the fast simulator
exactly as published. At the settings where we could run both, it produces
fewer mutants than the cell-by-cell simulator of the same paper (their
Algorithms~3 and~4): at $t_p=9$ with $p=2\times10^{-3}$ a culture has $134$
mutants on average under Algorithm~4 and $309$ under Algorithm~2, and under the
two-stage rates $(10^{-3},5\times10^{-3})$ with $\tau=4$ the means are $198$ and
$499$ ($3{,}000$ cultures each). The two use the same symbol $p$ but not the
same quantity: Algorithm~4 draws $\mathrm{round}(pZ)$ mutation events, while in
Algorithm~2 each daughter cell mutates independently with probability $p$. We
did not reconcile them, because every method here sees the same simulator and
the same truths, so no comparison among methods depends on it; but $p$ is to be
read in the sense of Algorithm~4 when set against \citeauthor{lu2023}'s Table~4,
which uses it too, and not as a per-division probability.

\subsection{Identifiability}
\label{sec:sim3D_identifiability}

The data say how much the summary can determine. On the rows with $\bar d>0$ the
correlation of $\log_{10}\bar d$ with $\log_{10}p_2$ is $0.76$, with
$\log_{10}p_1$ $0.07$, with $\tau$ $0.04$ and with $\log_{10}\delta$ $0.12$: the summary responds strongly to $p_2$, weakly to
$\delta$ and $p_1$ and barely to $\tau$, as in
\citeauthor{lu2023}'s Figures~3--4, which show multimodal $p_1$ and $\tau$
marginals. The reason is structural: mutations arising before $\tau$ are rare
because few cells exist that early, so $p_1$'s contribution to the mutant count
at $t_p=20$ is swamped by $p_2$'s. A fair evaluation therefore reports error
per parameter, on the $\log_{10}$ scale for $p_1,p_2$: for a weakly identified
parameter the posterior mean sits wherever the prior puts its mass, so
natural-scale RMSE diverges without conveying anything.

\subsection{A zero-aware neural surrogate}
\label{sec:hurdle}

The surrogate of Section~\ref{sec:method} needs two changes in this setting. The first is
the zero mass. Where $\bar d=0$ with positive probability, a Gaussian model of
$\log_{10}\bar d$ is not defined, and flooring the data at an arbitrary constant
makes the surrogate fit the constant. We model the distribution of the features
$(\bar d,s)$ given $\theta$ as a \emph{hurdle} distribution,
\begin{equation}
\label{eq:hurdle}
\begin{split}
\Pr(\bar d=0\mid\theta)&=\pi_\phi(\theta),\\
(\log_{10}\bar d,\ \log_{10}s)\mid\bar d>0,\theta&\sim
\mathcal N\!\big(\mu_\phi,\ \mathrm{diag}\,\sigma^2_\phi\big),
\end{split}
\end{equation}
with a logistic head for $\pi_\phi$ and two Gaussian mean and log-variance
heads. ($s=0$ exactly when $\bar d=0$.) The likelihood of an observed data set
with features $(\bar d_{\rm obs},s_{\rm obs})$ is $\pi_\phi(\theta)$ if
$\bar d_{\rm obs}=0$ and otherwise
$(1-\pi_\phi(\theta))\,\mathcal N(\log_{10}\bar d_{\rm obs},\log_{10}s_{\rm obs};\mu_\phi,\mathrm{diag}\,\hat c^2\sigma_\phi^2)$.
The second change is the second feature. The GPS-ABC sampler of
\citeauthor{lu2023} compares both the mean and the standard deviation of the
observed statistic, with a separate Gaussian-process surrogate for each. A
surrogate for $\bar d$ alone would give DNN-ABC less information than the
method it replaces, so the network has the two heads for both features. In
GPS-ABC they are treated as independent given $\theta$, and our DNN-ABC does the
same, so that it differs from GPS-ABC in the surrogate and nothing else. The
assumption is not harmless: within a design point, the residuals of
$\log_{10}\bar d$ and $\log_{10}s$ have correlation $0.61$ overall and $0.87$ where
$p_2\le10^{-9}$, because both are driven by the same few large mutant clones. We
therefore also fit the surrogate with a correlation head,
$\rho_\phi(\theta)=0.99\tanh(\cdot)$, replacing the diagonal covariance in
Eq.~\eqref{eq:hurdle} by one with correlation $\rho_\phi(\theta)$ and the same variances, and call
that version DNN-ABC-$\rho$. Its held-out joint negative log-likelihood of the two features is $-3.26$
against $-2.90$ for the independent version (nats per data set, same test designs; the
fitted mean $|\rho_\phi|$ is $0.60$). Training minimises the binary
cross-entropy of the logistic head plus the Gaussian negative log-likelihood of
Eq.~\eqref{eq:nll} summed over the two features on the rows with $\bar d>0$,
with a mean-squared-error warm-up for the first twenty epochs so that the
variance head cannot mask a poorly fit mean. The scale factors $\hat c$ are
split-conformal (Section~\ref{sec:conformal}), one per feature.

Training uses all $10{,}000$ design points, split \emph{by design point}
($80/10/10$): the sampler queries the surrogate at parameter values it has never
seen, so a split by replicate, which leaves every design point in every split,
would measure the wrong thing. The held-out target carries irreducible
replicate-to-replicate noise; we estimate it from within-design-point scatter
and report accuracy as a multiple of that floor, a figure that is $1.0$ for a
perfect surrogate.

the released \texttt{mut\_bMBP\_rev.m} draws the number of cells as the sum of
\texttt{geornd} over a vector with one entry per founder, which in the second
stage means about $e^{\tau}$ entries, up to $4\times10^{8}$ at $\tau=19.9$, and
the MATLAB workers run out of memory. A sum of $Z_0$ independent geometric
variables is negative binomial, so we replace that line by a single
\texttt{nbinrnd} call; the distribution is identical and the original file is
left untouched.

\noindent\textbf{DNN-ABC.} The sampler is the same Metropolis--Hastings algorithm
with the same priors and proposal family, with the Gaussian process replaced by
the trained network. There is no refinement step, since the network is trained
once, and no Monte Carlo draws from the surrogate, so the acceptance
decision uses the predictive density directly. The paper's step widths
$(0.8,3.5,3.5,4)$ are given without their order; applied to the sharper
network likelihood, they accept only a few per cent of proposals, against the
paper's stated target of $20$--$40\%$. We therefore multiply them by a single
factor chosen on a pilot run (first six data sets of each case) to bring
acceptance into that range.

\noindent\textbf{NPE, and why it is here.} An amortized neural posterior estimator
learns $p(\theta\mid\bar d,s)$ directly from simulator draws
\citep{papamakarios2016,greenberg2019}, here with \texttt{sbi}
\citep{tejerocantero2020}. We include it for three reasons, each of which bears on a claim of the paper. First, it
tests, with the same simulations, what the other two methods add on top of them. In one
dimension there is little to gain by skipping the sampler; in four, the
alternative to a surrogate inside an MCMC kernel is to learn the posterior
itself, and the question is whether the sampler, and the surrogate's variance
model, are needed at all. NPE uses exactly the DNN-ABC training data, the same
two features and the same design-point split, so any difference is the
method, not the data. Second, it needs no chain, no acceptance step and no $\epsilon$, so it
separates errors that come from the surrogate's variance model from errors that
come from the kernel and sampler; this is what lets Section~\ref{sec:sim3D_sbc} attribute
DNN-ABC's mild overconfidence to the Gaussian predictive density and the surrogate's
error rather than to the sampler. Third, it is amortized: after training it returns
independent posterior draws for a new data set in about four seconds, which none of GPS-ABC,
DNN-ABC and exact ABC-MCMC can, so it shows what is gained, and what is paid
(about six hours of training), by amortizing. Because it conditions on the same two
features, it also gives a reference for how much the pair $(\bar d,s)$ can identify, which
is what supports the identifiability claim as a property of the statistic and not of either method. We
train on the rows with $\bar d>0$ only. The population minimiser of the NPE
objective is $p(\theta\mid x)$ at every $x$ in the support of the training data,
whatever its marginal, so discarding the rows where $\log_{10}\bar d$ is undefined
leaves the posterior at any observed $\bar d>0$ unchanged; every observed data set
here has $\bar d>0$. The prior is uniform on the box, to which the paper's
$\mathrm{TN}(\cdot,20)$ priors are flat to within a few per cent. We fit a
neural spline flow and a mixture-density network and keep the one with the higher
held-out log-probability on unseen design points, never one chosen on observed data.

\subsection{Surrogate fit and calibration}
\label{sec:sim3D_fit}

Table~\ref{tab:arch4D} compares the twelve architectures on held-out design points.
Nine of the twelve reach the data's noise floor on both features, with test
mean-squared error between $0.91$ and $1.02$ times the floor estimated from replicate scatter
(a ratio just below one is estimation error in the floor, not a better-than-perfect
fit). Only the two smallest networks, with $437$ and $773$ parameters, are clearly short of it
($1.13$--$1.15$ on $\log_{10}\bar d$), and beyond about $2{,}500$ parameters
capacity buys nothing measurable: an MLP with $2{,}565$ parameters and one with
$42{,}757$ are within about five per cent of each other. The residual networks add no accuracy
over plain MLPs. Coverage of the conformal-calibrated $95\%$ interval is between
$0.938$ and $0.945$ for every architecture, and the zero head ranks datasets with
$\bar d=0$ against $\bar d>0$ almost perfectly (AUC $0.9975$--$0.9979$ for all twelve).

The selection rule picks the $3\times128$ residual network: it has the best mean validation loss
($-3.342$, standard error $0.002$) and the next best, a $4\times64$ MLP, is $0.0045$ worse,
so it alone is within one standard error. We do not read this as a verdict on residual
networks. Three plain MLPs of $13{,}000$--$43{,}000$ parameters are within $0.02$ in
validation loss and two to six times faster on large batches, and nothing in what follows
depends on the choice. On held-out designs the selected network has test error
$0.934$ and $0.938$ times the floor on $\log_{10}\bar d$ and $\log_{10}s$, coverage
$0.943$ and $0.954$ after the split-conformal scale factors ($0.989$ and $1.034$, so the variance
heads were already nearly calibrated), and zero-head log-loss $0.054$.

The Gaussian-process baseline of GPS-ABC, fit to the original design size of $1{,}500$ points, is $1.45$ times the
floor on $\log_{10}\bar d$ alone ($2.37$ at $300$ points), with $0.915$ coverage of its nominal-$95\%$
interval ($0.914$), and it has no way to represent the $30\%$ of datasets with $\bar d=0$. The network is at $0.93$
times the floor, and at $0.96$ when trained on the same $1{,}500$ design points. This
baseline is a diagnostic of the surrogate, not a re-run of GPS-ABC; the latter, with the
authors' own code and its refinement step, is reported in Section~\ref{sec:gps}.

\subsection{Is it the data or the model?}
\label{sec:matched}

The neural surrogate is trained on $10{,}000$ design points and GPS-ABC starts from
$1{,}500$, so a gain over GPS-ABC could come from the surrogate or simply from more
simulation. We separate the two by training the chosen network on only the first $1{,}500$ design points
of the training split (the original design size), with every other part of the pipeline unchanged. It
is $0.964$ and $0.982$ times the floor on the two features, with coverage $0.946$ and zero-head AUC $0.998$,
against $0.934$, $0.938$, $0.943$ and $0.998$ for the full-data network, and its
ABC-MCMC posteriors are close to those of the full-data network (Table~\ref{tab:rec4D}, rows ``DNN-ABC (1,500)''; for example the RMSE of $\log_{10}p_2$ is
$0.077$ against $0.078$ in case~1 and $0.086$ against $0.088$ in case~2). The extra training data
buys almost nothing here, which means that any difference from GPS-ABC at the same
design size cannot be attributed to the amount of simulation.

\subsection{Cost}
\label{sec:cost}

A DNN-ABC chain of $35{,}000$ iterations ($10{,}000$ for adapting the proposal and $5{,}000$ of burn-in, both discarded, then
$20{,}000$ retained) takes about $40$ seconds on one core; training the surrogate
takes about ten minutes. NPE, once trained, returns $20{,}000$ independent draws for a new data set in about four
seconds, but training the neural spline flow took $5.6$ hours on the shared server
(the mixture-density alternative took $49$ minutes and had the lower held-out log-probability, $-1.734$ against $-1.678$).

\subsection{Calibration over prior draws}
\label{sec:sim3D_sbc}

Coverage at a fixed truth cannot separate a calibrated posterior from an uninformative one: an
interval that spans the prior covers any truth, and in Table~\ref{tab:rec4D} the intervals for $p_1$
and $\tau$ nearly do. We therefore evaluate calibration by simulation-based calibration \citep{talts2018}
over truths drawn from the prior. For each of $K=500$ truths drawn uniformly from the box we simulate a data set of
$J=100$ cultures, compute each method's posterior and record the rank of the truth among $1{,}000$ posterior
draws; a calibrated posterior gives uniform ranks and central intervals with their nominal coverage,
whatever the identifiability. We also report posterior contraction, the share of prior
variance removed, $1-\overline{\mathrm{Var}}_{\mathrm{post}}/\mathrm{Var}_{\mathrm{prior}}$.
NPE is trained on data sets with $\bar d>0$ and so can only be scored on those ($364$ of the $500$);
ranks are uniform conditionally on any event defined by the data if the posterior is correct, so the
restriction is valid, and we score DNN-ABC on the same $364$. GPS-ABC is not included: it would need
hundreds of chains, each of which takes days.

Table~\ref{tab:sbc4D} separates two things that the fixed-truth coverage runs together. NPE is the best
calibrated method: its $95\%$ intervals cover $0.942$, $0.964$, $0.948$ and $0.942$ of the truths for
$\log_{10}p_1$, $\log_{10}p_2$, $\tau$ and $\log_{10}\delta$, all within about $1.3$ standard errors of nominal, and
its ranks are uniform at the $2\%$ level in every cell. The surrogate-in-MCMC methods are sharper and
overconfident. DNN-ABC covers $0.885$ for $\log_{10}p_2$, nearly six standard errors short of $0.95$, and $0.909$ and
$0.923$ for $\tau$ and $\log_{10}\delta$. It removes $0.98$ of the prior variance of $\log_{10}p_2$ against $0.87$ for NPE, which is where
the extra sharpness, and the miscalibration, come from; and for $\tau$ it removes $0.14$ of the prior variance where NPE removes
none ($-0.01$), so that part of what it learns about $\tau$ is not in the data. Modelling the correlation of the two features
makes the ranks more uniform ($\chi^2$ $p=0.51$ for $\log_{10}p_2$ and $0.98$ for $\log_{10}\delta$, against $0.17$ and $0.04$),
and removes more variance of $\log_{10}\delta$ ($0.63$ against $0.58$, and $0.62$ for NPE), but does not restore nominal
coverage ($0.896$, $0.901$ and $0.901$ for $\log_{10}p_2$, $\tau$ and $\log_{10}\delta$). The independence assumption inherited from GPS-ABC is therefore not the main
reason for the overconfidence. We have not identified it; candidates are the Gaussian form of the predictive
density of the log-features, which NPE does not assume, and the surrogate's own error away from the training points.
Rank histograms are in Supplementary Figure~S1.


\subsection{Comparison with GPS-ABC}
\label{sec:gps}

\noindent\textbf{How to read the extra width.} GPS-ABC's wider interval is a loss of precision, not accuracy. Its surrogate carries the Gaussian-process error

\section{Discussion}
\label{sec:discussion}
% =============================================================================

The two studies answer the question of Section~\ref{sec:intro} with a condition,
not a verdict. \emph{A surrogate improves an ABC inference where surrogate error
is what limits it, and a neural surrogate removes the cost that limits a GP.}
In Study I surrogate error binds: a heteroscedastic network gives tighter
intervals than a GP and a flat query cost. In Study II it binds more: the response
surface is zero-inflated, spans four decades and has strongly correlated features, and a
Gaussian process fit to the original design's $1{,}500$ points sits at $1.45$ times the data's noise
floor ($2.4$ at $300$ points) while the network sits at $0.93$ times it, and at $0.96$ when trained on the same $1{,}500$ points. The cost is the other half: one
GPS-ABC chain of $20{,}000$ iterations is projected to take at least four days (linear extrapolation from the $10.6$ hours that $2{,}000$ iterations took, with the cost per iteration rising as the chain runs), because the Gaussian process is refit, and grows,
whenever an accept/reject decision is uncertain, while a DNN-ABC chain of $35{,}000$ iterations takes about $40$ seconds
and NPE returns independent draws in four seconds once trained. On the same data sets and against the original authors' own sampler, DNN-ABC and NPE are not distinguishable from GPS-ABC in the accuracy of the posterior median for the identified parameters and give a $95\%$ interval for $p_2$ that is $1.6$ to $3.6$ times shorter (Section~\ref{sec:gps}); the shorter intervals are sharper than GPS-ABC's and, for DNN-ABC, a little too short.
The noise-floor measurement is cheap and tells which regime one is in; we recommend making it before any
surrogate comparison.

The control of Section~\ref{sec:matched} qualifies how this should be read. A network
trained on only $1{,}500$ design points, the size of the original design, is as good as one
trained on $10{,}000$, so the advantage over the GP is not that the network can use more simulation.
It is the model class: a hurdle distribution with input-dependent variances for a pair of features.

The second finding concerns identifiability. The summary statistic identifies
$p_2$, and $\delta$ loosely, and says almost nothing about $p_1$ or $\tau$: the $95\%$ intervals
for those two span $94\%$ and $92\%$ of the prior range. An NPE trained directly on simulator draws, with no
surrogate and no acceptance kernel, and a surrogate substituted into an MCMC kernel agree on this, which is evidence that the
ceiling belongs to the summary statistic and not to either method. A practical consequence is that a better emulator cannot
repair a weakly identified parameter; a richer summary than $(\bar d,s)$ is the lever.

The third finding is about calibration. Split-conformal calibration is a strong, distribution-free guarantee and it holds
for the surrogate's regression problem (coverage $0.943$ and $0.954$ for the two features). It says nothing about the
coverage of the posterior built on it. Over truths drawn from the prior, NPE is calibrated ($95\%$ intervals cover $0.94$--$0.96$) but
less sharp on $p_2$ (it removes $0.87$ of the prior variance, against $0.98$ for DNN-ABC), while the surrogate-based
samplers are sharper and overconfident ($0.885$ for $p_2$, nearly six standard errors below nominal, and $0.90$--$0.93$ for
the others). At a fixed truth, the two look alike. We therefore recommend simulation-based calibration over prior draws, together with posterior
contraction, as the routine check for any surrogate-based likelihood-free sampler. The reason for the overconfidence is
open. We found that the two features are correlated ($0.61$) and that GPS-ABC's treatment of them as independent is wrong
in that sense; modelling the correlation improves the held-out joint likelihood and the uniformity of the ranks but not the coverage
($0.896$ for $p_2$), so it is not the main cause. The Gaussian form of the predictive density, which NPE does not assume, and
surrogate error away from the training points are the remaining candidates.

Two architectural lessons recur. In Study I the dominant factor was not the activation function but the presence of
BatchNorm \citep{ioffe2015}: its per-minibatch statistics are counter-productive for a smooth regression on a bounded,
one-sided domain, and removing it improved the fit eleven-fold. In Study II no architectural choice mattered much: nine of
twelve candidates sit within $10\%$ of the noise floor, residual networks add nothing over plain MLPs, and only the two
smallest networks ($\le 773$ parameters) are clearly worse. The practical lesson is to let the symmetry of the input choose the
architecture family \citep{radev2020} and to measure the floor before searching.

\noindent\textbf{Limitations.} This is a simulation study under known ground truth, with no application to real
fluctuation-experiment data as in \citet{lu2023}; only that can speak to misspecification. Study II has two truth cases with
$100$ data sets each for the neural methods. GPS-ABC is run on five of those data sets per case and for $2{,}000$ (the first $500$ discarded)
iterations per chain, not the original study's $20{,}000$, because one chain takes days; its comparison with
the neural methods is therefore indicative, and what it establishes firmly is its cost. The fast simulator is that of the original
paper; its $p$ is not the per-division probability of the exact simulator (Section~\ref{sec:groundtruth3D}), which does not affect any comparison here but
matters for interpreting the estimates. Our data generator is tested against the original authors' released training data at their
design points, not against their observed data sets, which are not public. Study I uses $40$ replicates against
\citeauthor{lu2023}'s $100$, and we report Monte Carlo standard errors throughout so that unresolved differences are not
over-interpreted. The prior is bounded to the original study's box. NPE is trained on data sets with $\bar d>0$ and so does not
answer for data with no mutants at all. Finally, why the surrogate-based samplers are overconfident, and whether a
kernel-side correction restores nominal coverage, is left open.

\section{Reproducibility}
\label{sec:repro}
% =============================================================================

\noindent\textbf{Code and data.} All code, data, trained weights and the exact configuration for every table and figure are in
the public repository \url{https://github.com/sletch1/DNN-ABC-mutation-rates}. The one-dimensional and two-stage training
sets are committed as plain-text CSV files with self-documenting headers; the two-stage set is regenerated in about a minute by
\texttt{4D/datagen/gen\_training.py}, and its observed data sets by \texttt{4D/datagen/gen\_observed.py}. Every random stream is
seeded, and the output of the data generator does not depend on the number of cores. The original authors' released MATLAB code
is included unmodified; the one function we replace for the GPS-ABC runs, and the checkpointing copy of their sampler, are in
\texttt{4D/gps\_abc/patched/} with the reasons stated at the top of each file, and the places where the published paper and the released code
disagree, with the side we took, are listed in \texttt{paper\_code\_discrepancy.md}.

\noindent\textbf{Environment.} All code is Python (\texttt{numpy}, \texttt{pandas}, \texttt{scipy}, \texttt{matplotlib},
\texttt{scikit-learn} for the GP baseline, \texttt{torch} for the surrogates, \texttt{sbi} for NPE; minimum versions in
\texttt{requirements.txt}) except the GPS-ABC baseline, which is the authors' MATLAB (R2022b with the Statistics and Parallel
Computing toolboxes). No GPU is required. The heavy steps were run on a 32-core server; on it the architecture search takes
under an hour, the DNN-ABC chains for $200$ data sets about thirty minutes, NPE training about six hours and each GPS-ABC chain days.

\noindent\textbf{Running it.} Study I has a single entry point, \texttt{1D/run\_all.py}. Study II is a short sequence of
scripts documented in \texttt{4D/README.md}: data generation, the architecture search (\texttt{server/run\_search\_4d.sh}), DNN-ABC,
NPE and calibration (\texttt{server/run\_study2.sh}), the matched-budget and correlated-feature variants
(\texttt{server/run\_matched.sh}, \texttt{server/run\_corr.sh}), GPS-ABC (\texttt{server/run\_gps\_case.sh}) and the analysis
(\texttt{analysis/study2\_analysis.py}, which writes every table and figure that the manuscript includes).
All Study II tables are generated as \LaTeX{} fragments by \texttt{analysis/make\_tables\_tex.py}, so no number in them is copied by hand.

\noindent\textbf{Validation scripts.} \texttt{4D/tests/validate\_vs\_published.py} tests the data generator against the original
authors' released training data (it needs those files, which are not redistributed);
\texttt{4D/tests/test\_sim.py} checks the simulators against each other and the design for completeness.

\section{Conclusion}
\label{sec:conclusion}
% =============================================================================

A heteroscedastic neural surrogate, calibrated by split-conformal prediction and substituted for the Gaussian process inside
\citeauthor{lu2023}'s ABC-MCMC sampler, gives tighter intervals at matched accuracy and a $68$ to $2{,}381$-fold speedup over
the exact sampler in the one-dimensional benchmark. In the four-parameter two-stage model, which is the main study and is run in the
original study's own regime, the surrogate has to represent a response that is exactly zero for $30\%$ of data sets, spans four
decades and has two strongly correlated features; a zero-aware network does this at the data's noise floor where a Gaussian
process fit to the original design's $1{,}500$ points is $1.45$ times above it, and it needs no more than those $1{,}500$ design points to do so. Against the original authors' own sampler, run on the same data sets, it matches GPS-ABC's accuracy on the identified parameters with $95\%$ intervals for $p_2$ that are $1.7$ to $3.6$ times shorter, in about forty seconds per data set where a GPS-ABC chain takes days; the shorter intervals are mildly overconfident.
An amortized NPE trained on the same simulations agrees with it on what the data identify: $p_2$ well, $\delta$ loosely, and $p_1$ and $\tau$ not at all
from the pair $(\bar d,s)$. NPE is the better calibrated of the neural approaches over truths drawn from the prior, and the
surrogate-based samplers are sharper and mildly overconfident.

The general lessons are three. Measure the noise floor before comparing architectures or surrogates, because it predicts whether
a comparison can report anything. Do not read a surrogate's regression calibration as the calibration of the posterior built on it;
check the latter with simulation-based calibration over prior draws and posterior contraction, because fixed-truth coverage
saturates at one for weakly identified parameters. And do not expect a better emulator to repair a parameter the data do not identify. These
conclusions should apply beyond this model to ABC procedures built on a regression surrogate for an expensive simulator.
